로봇은 왜
움직인 뒤 다시 봐야 할까

피드백 루프에서 PID 항을 거쳐, 같은 조건의 응답 비교로 이어지는 현재 제어 학습 기록.

교육 진행 중 현재: 피드백·PID·튜닝 다음: 응답 로그 확인

로봇은 왜 움직인 뒤 다시 봐야 할까? 피드백은 현재 상태를 다시 읽어 오차를 만드는 단계이고, PID는 그 오차의 크기·누적·변화율을 나눠 다음 명령을 계산한다. 튜닝은 gain을 크게 만드는 일이 아니라 같은 조건의 응답을 비교해 선택하는 일이다.

읽는 시간 5분 측정 → 오차 → PID → 응답 비교

01

지금 수업에서 다시 이어 본 세 장면

세 Shorts는 센서 재측정 → 오차 분해 → 응답 비교로 이어진다. P는 현재 차이에, I는 오래 남은 차이에, D는 변화 방향에 반응한다. 한 번에 한 항목만 바꾸고 진동·정착 시간·출력 한계를 함께 봐야 튜닝 결과를 설명할 수 있다.

초보자인 내가 이해한 PID는 만능 버튼이 아니다. 마찰, dead zone, 출력 한계가 있으면 공식만으로 결과를 단정할 수 없다. 그래서 실제 장비는 속도와 힘을 낮추고 주변을 비운 뒤 조건을 고정해 다시 본다.

02

오늘 확인한 것과 아직 남은 것

현재 커리큘럼 6단계 ‘계획하고 정확히 움직이기’에서 target, measured value, error, output을 같은 시간축에 놓는 법을 배우는 중이다. 내가 배운 내용을 정리해 가는 개인 학습 레포인 DAPIER에도 기록이 계속 쌓여 간다. 오늘 확인한 것은 개념의 연결과 비교 기준이며, 실제 모터·엔코더 배선과 일정한 sample time의 제어 루프는 아직 실행하지 않았다.

다음 수업 전에는 안전한 저속·짧은 구간에서 target, time, encoder, error, PWM 다섯 열을 남기는 방법을 점검하겠다. 하드웨어가 없으면 target step을 가정해 P·PI·PID 응답 표를 만들고 gain을 한 번에 하나만 바꾸겠다. 중단 조건과 출력 제한도 함께 기록할 예정이다.

03

11월까지의 계획과 다음 질문

숙련자에게 남길 질문은 제어 로그 계약이다. target·feedback 단위, timestamp와 실제 적용 시각, 흔들리는 sample time에서 D항 제한, saturation·안전 정지 기록을 어떻게 고정해야 비교가 재현될까?

11월까지의 계획: 작은 시뮬레이션 또는 안전한 실습에서 응답 로그를 반복하고 센서·제어·평가를 한 실험 단위로 묶겠다. 교육은 진행 중이며, 직접 확인한 수치와 실패만 차례로 추가하겠다.
