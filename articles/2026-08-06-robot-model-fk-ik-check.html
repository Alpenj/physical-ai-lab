로봇 모델이 먼저 있어야 하는 이유:
관절각에서 손끝까지

관절값에서 손끝을 계산하고 손끝 목표에서 관절값을 찾는 과정이 왜 같은 모델을 필요로 하는지 적는다.

교육 진행 중 현재: 로봇 모델링·정기구학·역기구학 다음: 제약과 좌표 변환 검증

관절 각도 세 개를 넣으면 로봇 팔 끝은 어디에 있을까? 반대로 손끝을 원하는 위치에 두려면 관절을 몇 도 돌려야 할까? 세 Shorts를 이어 보며, 이 질문이 같은 로봇 모델을 사이에 둔 왕복 확인이라는 생각이 들었다. 지금은 움직이기 전에 숫자가 무엇을 뜻하는지 확인하는 단계다.

읽는 시간 5분 모델 → 계산 → 안전한 다음 확인

01

지금 수업에서 다시 배우는 두 방향의 번역

지금은 로봇 모델링 모듈에서 모델·정기구학·역기구학을 따라가고 있다. 로봇 모델은 링크와 관절, 회전축, 움직임 제한을 소프트웨어로 적은 설계도다. 정기구학(FK)은 관절값으로 손끝의 위치와 자세를 계산하고, 역기구학(IK)은 손끝 목표에서 가능한 관절값을 찾는다. FK는 ‘관절에서 손끝으로’, IK는 ‘손끝에서 관절로’ 가는 번역기다.

첫 번째 Shorts는 왜 실제 로봇보다 모델이 먼저 필요한지 물었다. 모델이 없으면 관절 숫자와 실제 부품의 축·길이·범위를 같은 대상으로 해석하기 어렵다. 두 번째는 관절각이 손끝 위치로 이어지는 FK를, 세 번째는 목표 위치에서 관절각을 찾는 IK를 다뤘다. IK에는 답이 여러 개이거나 관절 제한·충돌·특이점 때문에 답이 없을 수도 있다. ‘계산 결과가 나왔다’와 ‘안전하게 움직일 수 있다’는 같은 말이 아니다.

“모델은 움직임을 대신하는 답이 아니라, 계산과 안전을 같은 기준으로 묶는 약속이다.”

02

내가 배운 내용을 기록하는 방식

DAPIER는 내가 수업과 실습에서 배운 내용을 정리해 가는 내 학습 레포다. 이 글에서 DAPIER를 외부 교재나 권위 자료처럼 참조하는 것은 아니다. 오늘의 이해는 세 Shorts와 현재 수업에서 다룬 모델·FK·IK를 내 말로 다시 적은 것이고, DAPIER에는 앞으로 직접 확인한 코드와 결과가 계속 쌓일 예정이다.

이 흐름은 현재 수업에서 이해한 구조를 간단히 그린 것이다. FK·IK를 실제 장치에서 실행했다는 증거로 쓰지 않으며, 실제 손끝 목표를 넣어 해를 선택한 결과도 아직 확인하지 않았다. 나는 DAPIER를 새로 공부하는 것이 아니라, 배운 내용을 내 학습 기록으로 정리해 가는 중이다.

03

오늘 확인한 것과 아직 남은 것

오늘 확인

세 Shorts가 같은 질문으로 이어지고, 관절 이름·단위·안전 범위를 함께 봐야 한다는 점을 이해했다.

아직 미확인

실제 팔에 목표 손끝 자세를 넣어 IK 해를 고르고, 그 결과가 하드웨어에서 안전하게 도달하는지는 아직 실행하지 않았다.

다음 확인

2링크 평면 팔의 FK와 간단한 수치 IK를 Python으로 계산하고, 같은 관절 순서와 timestamp로 결과를 비교한다.

다음 수업 전에는 시뮬레이션과 계산 결과부터 맞춰 보려고 한다. 실제 하드웨어는 그 뒤의 별도 확인으로 남긴다.

04

11월까지의 계획과 다음 질문

11월까지의 계획은 모델에서 FK·IK, 워크스페이스와 충돌, ROS 2·TF, episode와 평가로 넓히는 것이다. 끝낸 목록이 아니라, 실행한 것과 다음에 확인할 것을 나누는 진행표다. 숙련자용 질문은 이것이다. IK의 여러 해 중 하나를 고를 때 관절 단위, frame ID, timestamp, joint limit, 안전 필터, 평가 기준을 하나의 데이터 계약으로 어떻게 고정하고 로그로 재현할 것인가?
